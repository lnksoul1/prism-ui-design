# 非专业人员用 AI 生成 UI 的痛点分析与 Prism 优化方案

> 版本：v1.0 · 日期：2026-08
> 范围：`prism-ui-design-mcp`（MCP 服务端 + Dashboard）
> 依据：全仓源码审计（MCP 工具 / REST+WS 双通道 / 客户端交互）+ 外部开源项目调研
> 配套实现：本仓库代码（prompt-executor v2、explain 工具、客户端引导体验），全部测试通过

---

## 一、结论摘要

Prism 已经具备很强的"工程能力"（71+ MCP 工具、DTCG 令牌、a11y 审计、画布协作、导出多格式），但这些能力大多是为 **AI Agent 或设计师** 设计的。站在**非专业人员**（不会写代码、没有设计词汇、第一次打开工具）的视角，存在一条清晰的体验断层：

> **会打字，但不知道打什么；打得出来，但系统听不懂；听懂了，但改不到点上；改完了，但看不懂结果。**

本轮优化围绕这四个断层做了四组改动：

1. **指令引擎 v2（`src/prompt-executor.ts`）**：新增 10+ 类"日常说法"意图（改文字、字太小、间距大一点、整体调亮、换成衬线字体、检查对比度等），听不懂时不再沉默排队，而是**返回可点击的示例指令**。
2. **反向语义解释（`design_explain_design` + `/api/explain` + Dashboard「解读」按钮）**：把设计令牌翻译回大白话，并给出"你可以这样说"的下一步指令——**用示例教用户学会设计词汇**。
3. **模板非破坏性应用**：页面非空时套模板不再报错，自动开新页面——消除"先清空"这个反直觉的前置条件。
4. **客户端引导体验**：空画布示例指令、"试试这些"可点击建议条、一键"新标签页打开"独立预览、双语（中/英）全覆盖。

同时修复了工作区中未完成的分支（StoredState 类型缺陷、page-link 契约不一致、REST 错误码），**测试从 371 → 392 项全绿**。

## 二、非专业人员的六大痛点（痛点 → Prism 现状 → 对标方案）

### P1. 空白页瘫痪：不知道第一句话该说什么

- **现象**：非专业人员没有"hero / CTA / 配色 / 留白"等词汇，面对输入框只会写"帮我做个好看的页面"，AI 生成结果随机、用户无法继续迭代。
- **Prism 旧状**：输入框 placeholder 只有一句示例 + 5 个快捷 chips（深色/浅色/SaaS/电商/清空），空画布有 6 个入口按钮但都是"入口"而非"内容"。
- **对标**：v0 / Lovable 用**模板画廊**（缩略图选起点）；Claude Artifacts 用**即时预览**降低"想象成本"；Google Stitch 验证了**形容词驱动**（"活泼/工业风"）。
- **本轮改动**：
  - 空画布新增"或直接说一句话试试"示例指令行（改主色 / 生成模板 / 字大一点 / 调亮），一键执行、本地即生效，**无需 Agent 也在线**；
  - 快捷 chips 从 5 个扩到 9 个，且全部中英双语；
  - `design_explain_design` 返回 7 条"你可以这样说"，把词汇教学嵌入工具本身。

### P2. 指令死胡同：说了系统听不懂，然后就没有然后

- **现象**：非专业说法（"字太小了""太素了""感觉挤"）不匹配 Agent 工具参数，指令排队后无反馈，用户以为系统坏了。
- **Prism 旧状**：内置指令引擎只覆盖 ~15 条规则（颜色/主题/风格/模板/组件/撤销/清空），未匹配的指令**静默排队**，Dashboard 永远显示"等待 Agent 处理…"。
- **对标**：Lovable 的"Visual Edits"用**直接操作 + AI 补全**绕开语言障碍；OpenUI 用**对话 + 实时渲染**让每次输入都有可见结果。
- **本轮改动**：
  - 指令引擎 v2 新增意图：**改文字**（"把标题改成「…」"）、**相对尺寸**（"字太小了/间距更紧凑/整体大一点"）、**明暗**（"整体调亮一点"）、**圆角**（"改成直角/圆角大一点"）、**字体**（"换成衬线字体"）、**文字颜色**（"把文字改成蓝色"）、**对比度检查**、**重做**；
  - 未匹配指令：REST 与 WS 双通道都会**即时回执**（`executed/summary/suggestions`），Dashboard 弹出**可点击的建议条**，点击即执行——死胡同变成引导。

### P3. 改不到点上：生成结果"差一点"，但不会改

- **现象**：AI 生成的页面 80% 满意，剩下 20%（字号、间距、圆角、文案）非专业人员既不会描述、也不会直接改。
- **Prism 旧状**：属性检查器可以改组件文本/颜色，但**全局的"感觉"问题**（整体太挤、字太小）只能改令牌面板——令牌名词（`color-primary`、`space-md`）对非专业者是另一门外语。
- **对标**：Claude Design 的**自定义滑块**（实时调间距/颜色/布局）被验证为"AI 生成 + 可视化精修"标准范式；Prism 已有令牌面板，但缺少**自然语言直达令牌**的通道。
- **本轮改动**：把"感觉问题"翻译成令牌操作并做成一句话指令（见 P2 意图列表）；`/api/explain` 的 facts 把令牌状态用中文描述出来（"主色：紫色 #7C3AED（鲜艳的紫）"），让令牌面板的后续操作有了入口地图。

### P4. 破坏恐惧：怕把好好的设计改坏

- **现象**：非专业人员不敢试错，因为不知道"试一下"之后能不能回去。
- **Prism 旧状**：Undo/Redo（50 步）、自动保存、版本快照、模板保存都齐全；但**套模板要求先清空**——用户已经画了一半，点模板被拒绝，试错成本陡然升高。
- **对标**：Lovable/OpenUI 的每次迭代都在**新分支/新版本**上进行；Figma 式"图层 + 撤销"是通用安全感来源。
- **本轮改动**：模板应用改为**非破坏性**——页面非空时自动新建页面再套模板（含 prompt 引擎与空状态入口一致）；新增"重做"指令补齐撤销闭环。

### P5. 结果读不懂：不知道导出的是什么、能拿来干什么

- **现象**：拿到 HTML/React/Vue/Flutter 代码，非专业人员不知道如何"看到"它，更不知道如何交付。
- **Prism 旧状**：导出弹窗有 10 种格式标签（选择过载），截图按钮提供 PNG；没有"打开独立页面"的一步操作。
- **对标**：OpenUI 的"单文件可运行产物 + 框架切换"、Claude Artifacts 的"就地运行"都是为"看到结果"服务；v0/Lovable 主打**一键部署**。
- **本轮改动**：导出弹窗新增**"新标签页打开"**——HTML 导出直接变成独立标签页，可保存为单文件、可发给别人看；截图（PNG/HTML 降级）保留。

### P6. 质量没底：不知道自己的设计"行不行"

- **现象**：非专业人员担心"这个配色看不清吧？"，但没有工具把质量用大白话告诉他。
- **Prism 旧状**：`design_audit_accessibility`（9 条 WCAG 规则）和冲突检测是 Agent 侧能力，Dashboard 空状态有一张对比度卡片，但没有持续可见的"质量解读"。
- **对标**：ui-toolkit-mcp 的"生成即审计"、Better Design 的 WCAG 规则集是开源设计 MCP 标配。
- **本轮改动**：指令"检查一下对比度"把冲突检测暴露给普通用户（一句话即可）；`/api/explain` 与「解读」弹窗把对比度问题、风格性格用大白话报出来（"发现 1 个对比度问题，输入『检查对比度』查看"）。

## 三、开源项目对标（2026-08 时点）

| 项目 | 核心机制 | 对非专业者的启示 | Prism 对应/差距 |
|---|---|---|---|
| **wandb/openui** | 对话生成 + 实时渲染 + 一键转 React/Svelte | 每次输入都有**可见结果**；单文件产物 | 画布实时渲染已有；新增"新标签页打开"补上"可见+可分享"闭环 |
| **tldraw make-real / SawyerHood/draw-a-ui** | **画线框 → AI 转真实 UI** | 画比说门槛低；绕过词汇问题 | 已有画布模式 + `design_draw_canvas`（方案A），保持优势 |
| **Lovable（已开源）** | Visual Edits：点画布直接改，AI 补全 | **直接操作 + AI** 是兜底；试错零成本 | 属性检查器已有；本轮补自然语言直达令牌 + 非破坏模板 |
| **v0 / shadcn/ui** | 组件化生成 + 可预期原语 | 组件即词汇（"定价表"比"pricing section"好懂） | 41 组件类型已有；指令引擎支持中文组件名 |
| **Claude Design（Anthropic）** | 对话 + 内联批注 + **自定义滑块** | "生成 + 滑块精修"范式；解释性反馈 | 令牌面板已有；本轮"解读"补解释性反馈 |
| **OpenUI / Claude Artifacts** | 就地运行预览 | 非专业者只需要"看到" | 新增独立标签页预览 |
| **ui-toolkit-mcp / Better Design** | 生成即审计、DTCG、规则集 | 质量兜底自动发生 | a11y 审计已有；对比度检查口语化 |
| **Google Stitch** | 形容词 → 风格系统 | 形容词是最大公约数词汇 | `design_semantic_style` 已有（正向）；本轮补**反向**（设计 → 形容词） |

**Prism 的差异化结论**：正向语义（形容词→令牌）+ 反向解释（令牌→大白话）+ 画布绘制三者闭环，是当前开源生态中没有完整覆盖的组合。本轮把"反向解释"落地后，非专业者可以在 **说 → 看 → 说** 的循环里被工具教会设计词汇，而不是被词汇挡在门外。

## 五、后续建议（未在本轮实施）

| 方向 | 理由 | 建议 |
|---|---|---|
| **风格对比画廊** | P3 的"选一个看看"需求：一次生成同组件树 × 3 种风格的并排 HTML，不改变当前状态 | 新工具 `design_compare_styles(styles[])`，复用导出器 + 纯函数渲染 |
| **指令语义升级为 LLM 意图库（可选依赖）** | 规则引擎覆盖面有限 | 保持零依赖规则层，外部 Agent 通过 `design_check_prompts` 兜底（现状已支持） |
| **设计健康分常驻** | P6 需要持续可见的质量信号 | 把 a11y 审计分数放进 Dashboard 顶栏状态区 |
| **多候选版本对比视图** | P4/P5 的选择成本 | 版本面板加"并排对比"渲染 |
| **分享链接 / 单文件 zip** | P5 的交付 | 独立标签页已有；zip 打包（HTML + 图片资产）是自然延伸 |

## 六、验证方式

```bash
npm test                 # 392 项全绿（含新增 21 项）
npm run lint             # ESLint
npm run build            # tsc
TRANSPORT=http npm start # 打开 http://localhost:3100
```

Dashboard 手工验收路径（对应 P1–P6）：
1. 空画布 → 点击"把主色改成蓝色"示例 → 立即执行并提示；
2. 输入"字太小了，大一点" → 字号令牌整体放大；
3. 输入"帮我把配色优化得更高级一点" → 弹出 8 条可点击建议；
4. 页面有内容时输入"生成一个电商模板" → 自动新开页面，不报错；
5. 点击「解读」→ 大白话总结 + 点击建议自动填入输入框；
6. 导出 → HTML → 「新标签页打开」→ 独立单文件页面。
